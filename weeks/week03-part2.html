Part 2: Expected value and decision trees

Keywords

random variable, expected value, expected monetary value, decision tree, rollback, risk, binomial distribution

In part 1 we turned records into probabilities. In this part we assign monetary values to those probabilities, so that we can compare two options with uncertain outcomes and then estimate how many registered people will attend.

NoteWhere we are in this chapter

Our events team is planning a one-day training event and has three questions to answer:

  1. How many of the people who register will attend?
  2. Which of two catering vendors should we book?
  3. How many working days do we need to be ready?

In part 1 we started on the first question. The file Week3_Probability_Basics_Data.csv holds 100 registration records from past events. In those records, 83 of the 100 registered people attended, so the probability that a registered person attends is 0.83.

In this part we answer the second question. We use the file Week3_Decision_Tree_Data.csv, which holds 50 scenarios. In each scenario we compare a local vendor with an international vendor for the same catering contract. For each vendor, the file gives the probability that it delivers on time, the probability that it delivers late, and our profit or loss in each case. The vendor scenarios explains the file column by column. At the end of this part we return to the first question and use the probability of 0.83 to estimate how many people will attend an event with 120 registrations.

In part 3 we answer the third question, using two more files.

Random variables and probability distributions

Some numbers we can only know after something uncertain has happened. For example: our events team signs a catering contract with a local vendor. We do not yet know our profit from the event, because it depends on whether the vendor delivers on time or late. Until the delivery happens, our profit could take one of two values.

A number like this is called a random variable: a number whose value is decided by chance. The number of registered people who attend an event is another random variable, since we learn its value only on the day of the event.

Where the profit comes from

For example: imagine the event earns 20,000 USD from tickets and the local vendor charges 13,056.38 USD. If the vendor delivers on time, our profit is:

\[20{,}000 - 13{,}056.38 = 6{,}943.62 \text{ USD}\]

If the vendor delivers late, we must also buy emergency supplies, which cost 8,762.09 USD. Our costs are now greater than our income, so we make a loss:

\[20{,}000 - 13{,}056.38 - 8{,}762.09 = -1{,}818.47 \text{ USD}\]

The money we are left with at the end of each outcome is called the payoff. A positive payoff is a profit, and a negative payoff is a loss.

Probability distributions

A probability distribution lists every value a random variable can take, together with the probability of each value. For example: the local vendor delivers on time with probability 0.740 and late with probability 0.260. These probabilities come from scenario 1 of our data file, described in The vendor scenarios. So our profit has this distribution:

Two rules hold for every probability distribution:

  1. Each probability lies between 0 and 1.
  2. The probabilities add to 1, because the list covers every possible value: in Table 3.9, \(0.740 + 0.260 = 1.000\).

In each scenario our events team compares two vendors for the same catering contract: a local vendor and an international vendor. Each vendor has its own row, so the file has 100 rows, 2 for each scenario.

The file uses its own column names. It says “success” for an on-time delivery and “failure” for a late one. Table 3.10 translates each column into the words we use in this chapter.

For example: scenario 1 is the 2 rows with Group_ID 1. The first row holds the local vendor’s figures from Table 3.9.

The file stores each probability to 16 decimal places. In our hand calculations we round them to three, so 0.7397 becomes 0.740. Three decimal places are accurate enough for the decision and short enough to calculate by hand. In the tutorial, your spreadsheet uses the full figures, so its answers differ from ours by a few dollars.

Expected value

When we choose a vendor, we need one figure that sums up what each contract is worth to us before we know the outcome, and the expected value gives us that figure.

For example: suppose we signed the local vendor’s contract from scenario 1 100 times. With an on-time probability of 0.740, about 74 deliveries would arrive on time, each giving a profit of 6,943.62 USD. The other 26 would arrive late, each giving a loss of 1,818.47 USD. Our total over the 100 contracts would be:

\[74 \times 6{,}943.62 - 26 \times 1{,}818.47 = 513{,}827.88 - 47{,}280.22 = 466{,}547.66 \text{ USD}\]

Shared across the 100 contracts, that is \(466{,}547.66 \div 100 = 4{,}665.48\) USD per contract. This average per contract is the expected value of the contract.

We reach the same figure in one line by multiplying each payoff by its probability and adding the results:

\[EV = 0.740 \times 6{,}943.62 + 0.260 \times (-1{,}818.47) = 5{,}138.28 - 472.80 = 4{,}665.48 \text{ USD}\]

Each payoff counts in proportion to its probability: the on-time payoff contributes 74 per cent of its value and the late payoff 26 per cent. In general, the expected value of a random variable is:

\[EV = \sum p_i \, x_i = p_1 x_1 + p_2 x_2 + \dots\]

where \(x_i\) is the \(i\)th possible value of the random variable (here, a payoff in USD) and \(p_i\) is the probability of that value. The symbol \(\sum\) means “add up over every outcome”. The vendor file calls an on-time delivery a success and a late delivery a failure, so for a vendor the formula has two terms:

\[EV = p_{\text{success}} \times x_{\text{success}} + p_{\text{failure}} \times x_{\text{failure}}\]

An expected value measured in money is called the expected monetary value.

On any one contract we receive one of the two payoffs, either +6,943.62 USD or −1,818.47 USD. The expected value of 4,665.48 USD lies between them, and we receive it only as an average across many contracts.

Two vendors, one contract

In scenario 1 of the vendor scenario file (Table 3.11), the two vendors offer these outcomes, with probabilities rounded to three decimal places:

The local vendor’s expected value is 4,665.48 USD, calculated in Expected value. Calculate the international vendor’s expected value and decide which vendor we should book on expected value alone.

International vendor:

\[EV = 0.825 \times 11{,}552.23 + 0.175 \times (-2{,}298.97)\] \[= 9{,}530.59 - 402.32 = 9{,}128.27 \text{ USD}\]

With the file’s unrounded probabilities, your spreadsheet in the tutorial gives 4,663.15 USD for the local vendor and 9,123.24 USD for the international vendor. Rounding changes the two answers by 2.33 and 5.03 USD, and the choice stays the same.

Risk behind the expected value

An expected value sums up a contract in one number: the average payoff over many contracts. A single contract can give a payoff far from that average, so we also need to know how far. For example: imagine that contract A gives us 5,000 USD whatever happens, while contract B gives us a profit of 15,000 USD with probability 0.5, or a loss of 5,000 USD with probability 0.5. The two contracts have the same expected value of 5,000 USD:

\[EV_B = 0.5 \times 15{,}000 + 0.5 \times (-5{,}000) = 7{,}500 - 2{,}500 = 5{,}000 \text{ USD}\]

Contract A can never lose us money, and contract B loses us 5,000 USD half the time. So before we choose, we look at three more figures in a risk review.

The probability of a loss: For a vendor, this is the probability of a late delivery.

The worst outcome: This is the largest loss we can make on the contract. We need to ask whether we can absorb that loss.

The standard deviation of the payoff: This measures how far the payoff typically falls from the expected value. It is the same measure of spread as the standard deviation in chapter 1. The difference is that each squared distance counts in proportion to its probability, just as each payoff did in the expected value:

\[\sigma = \sqrt{\sum p_i \, (x_i - EV)^2}\]

For example: the local vendor in scenario 1 has an expected value of 4,665.48 USD. The on-time payoff lies \(6{,}943.62 - 4{,}665.48 = 2{,}278.14\) USD above it, and the late payoff lies \(-1{,}818.47 - 4{,}665.48 = -6{,}483.95\) USD below it. So the standard deviation is:

\[\sigma = \sqrt{0.740 \times 2{,}278.14^2 + 0.260 \times 6{,}483.95^2}\] \[= \sqrt{3{,}840{,}542 + 10{,}930{,}818} = \sqrt{14{,}771{,}360} = 3{,}843 \text{ USD}\]

When there are only two outcomes, the same answer comes from a shorter formula:

\[\sigma = (x_{\text{success}} - x_{\text{failure}}) \times \sqrt{p_{\text{success}} \, (1 - p_{\text{success}})}\]

The first bracket is the gap between the two payoffs. The late payoff is negative, so subtracting it adds its size: \(6{,}943.62 - (-1{,}818.47) = 6{,}943.62 + 1{,}818.47 = 8{,}762.09\) USD, and the standard deviation is:

\[\sigma = 8{,}762.09 \times \sqrt{0.740 \times 0.260} = 8{,}762.09 \times 0.43863 = 3{,}843 \text{ USD}\]

This is the same as the long formula. A wider gap between the two payoffs, or a probability nearer 0.5, gives a larger standard deviation.

Worked example 3.7

Reviewing the risk

Scenario 38 has the smallest gap in expected value between the two vendors of all 50 scenarios in the vendor scenario file (The vendor scenarios).

Calculate each vendor’s expected value and standard deviation. Compare the probability and the size of a loss. Then recommend a vendor, given that we can absorb a loss of up to 2,000 USD.

Expected values:

\[EV_{\text{local}} = 0.695 \times 6{,}854.85 + 0.305 \times (-1{,}237.64)\] \[= 4{,}764.12 - 377.48 = 4{,}386.64 \text{ USD}\]

\[EV_{\text{intl}} = 0.821 \times 8{,}286.90 + 0.179 \times (-3{,}822.62)\] \[= 6{,}803.54 - 684.25 = 6{,}119.29 \text{ USD}\]

Standard deviations, by the two-outcome formula, to the nearest dollar:

\[\sigma_{\text{local}} = (6{,}854.85 + 1{,}237.64) \times \sqrt{0.695 \times 0.305}\] \[= 8{,}092.49 \times 0.46041 = 3{,}726 \text{ USD}\]

\[\sigma_{\text{intl}} = (8{,}286.90 + 3{,}822.62) \times \sqrt{0.821 \times 0.179}\] \[= 12{,}109.52 \times 0.38335 = 4{,}642 \text{ USD}\]

Risk review:

The international vendor has the higher expected value and the lower probability of a loss. Its worst outcome is about three times the local vendor’s, and its payoff is more spread out.

Recommendation: We should book the local vendor. With the international vendor, a loss of 3,822.62 USD would happen about once in every 6 contracts, and that loss is greater than the 2,000 USD we can absorb. By booking the local vendor we give up \(6{,}119.29 - 4{,}386.64 = 1{,}732.65\) USD of expected value, and in return every outcome stays within our limit. If our reserves were larger, we would book the international vendor.

Decision trees

A decision tree sets out a decision on paper from left to right: the options we can choose from, the uncertain events that follow each option and the payoff at the end of every path. It is the probability tree from part 1 with one addition: points where we choose which branch to take.

We draw a tree in four steps:

  1. Put a decision node at the left and draw one branch for each option.
  2. At the end of each option, put a chance node and draw one branch for each outcome. Write its probability on the branch. The probabilities leaving a chance node add to 1.
  3. At the end of each outcome, put an end node and write the payoff.
  4. Roll the tree back from right to left, as described in Rolling back a tree, and mark the chosen branch.

In Figure 3.2, the vendor decision from worked example 3.6 is drawn as a tree.

Rolling back a tree

Rolling back a decision tree means working from the payoffs on the right towards the decision on the left. At each node we write a single value:

  • At a chance node, the value is the expected value of its branches.
  • At a decision node, the value is the value of the best branch, the one with the largest value. We strike through the branches we reject, as in Figure 3.2, where the rejected branch carries two short strokes.

In a one-stage tree, such as the vendor tree, rolling back is the expected value calculation from worked example 3.6. Rolling back is more useful when we face a second decision after a chance event. For example: we book an outdoor venue, and if it rains we must decide on the day whether to move indoors. We can only value the outdoor venue once we know what we would do in the rain, so we make the later decision first and work back to the first one.

Worked example 3.8

An outdoor venue with a fallback

In this illustrative example, separate from the data files, we can book an indoor hall for a guaranteed profit of 8,000 USD, or an outdoor venue. Outdoors, good weather (probability 0.7) gives a profit of 12,000 USD. In bad weather (probability 0.3) we decide on the day: move indoors at short notice for a profit of 4,000 USD, or stay outdoors and make a loss of 2,000 USD.

Draw the tree, roll it back and choose a venue. Then calculate how much the possibility of moving indoors is worth to us.

The tree: In Figure 3.3, the decision node at the left is the choice of venue, the chance node after “Outdoor venue” is the weather and a second decision node follows bad weather.

Step 1, the later decision: In bad weather, moving indoors gives a profit of 4,000 USD and staying outdoors gives a loss of 2,000 USD. We would move indoors, so we write 4,000 USD on the bad-weather decision node.

Step 2, the chance node:

\[EV_{\text{outdoor}} = 0.7 \times 12{,}000 + 0.3 \times 4{,}000\] \[= 8{,}400 + 1{,}200 = 9{,}600 \text{ USD}\]

Step 3, the first decision: The outdoor venue’s 9,600 USD exceeds the hall’s 8,000 USD, so we book the outdoor venue.

The value of the fallback: Suppose moving indoors were impossible, so we had to stay outdoors in bad weather.

\[EV = 0.7 \times 12{,}000 + 0.3 \times (-2{,}000)\] \[= 8{,}400 - 600 = 7{,}800 \text{ USD}\]

That is less than the hall’s 8,000 USD, so without the fallback we would book the hall. Being able to move indoors is worth \(9{,}600 - 7{,}800 = 1{,}800\) USD to us in expected value. When we negotiate the outdoor booking, we should secure that fallback in writing before signing.

Counting successes: the binomial model

Now we return to our first question: how many registered people will attend? Each registration has two outcomes, attend or stay away, and an event has many registrations. The binomial model gives the probability distribution of the number of successes in a fixed number of trials. Here a trial is one registration, and a success is a person who attends. The model applies when four conditions hold:

  1. There is a fixed number of trials, \(n\): here, the registrations.
  2. Each trial has two outcomes, success or failure: here, attended or no-show.
  3. The probability of success, \(p\), is the same for every trial: here, 0.83 from the records.
  4. The trials are independent: whether one person attends has no effect on whether another attends.

The fourth condition needs checking every time we use the model. For example: colleagues who registered as a group travel together, so they tend to attend or stay away together. Group bookings break independence, and attendance then varies more than the model predicts.

Where the binomial probabilities come from

We can see where the model comes from by drawing a probability tree. Take three registrations, each attending with probability 0.83. The tree has \(2 \times 2 \times 2 = 8\) paths, and because the registrations are independent, we multiply the probabilities along each path. Three of the paths have exactly two people attending, because the one person who stays away can be the first, the second or the third. Each of those paths has probability \(0.83 \times 0.83 \times 0.17\).

The general formula multiplies the number of paths by the probability of one path. The number of paths with exactly \(k\) successes is written \(\binom{n}{k}\) and read “n choose k”. For example: with three registrations and two attending, \(\binom{3}{2} = 3\), as in Table 3.17.

\[P(X = k) = \binom{n}{k} \, p^k (1 - p)^{n - k}\]

where \(X\) is the number of successes, \(n\) the number of trials, \(k\) the number of successes you want the probability of, and \(p\) the probability of success on one trial.

We rarely calculate it by hand, because a spreadsheet does it in one function: =BINOM.DIST(k, n, p, FALSE) gives \(P(X = k)\), and =BINOM.DIST(k, n, p, TRUE) gives the probability of \(k\) or fewer.

The mean and standard deviation of a binomial

The expected number of successes and its standard deviation have short formulas:

\[\mu = n \, p \qquad \sigma = \sqrt{n \, p \, (1 - p)}\]

where \(\mu\) (the Greek letter mu) is the expected number of successes and \(\sigma\) is its standard deviation.

For the three registrations, \(\mu = 3 \times 0.83 = 2.49\), and the expected value formula from earlier in this part gives the same figure: \(3 \times 0.5718 + 2 \times 0.3513 + 1 \times 0.0720 + 0 \times 0.0049 = 2.49\).

When \(n p\) and \(n (1 - p)\) are both at least 10, the binomial distribution has close to a normal shape. We can then estimate its probabilities with the z-scores and the normal table from chapter 2. The binomial counts whole people, and the normal model treats attendance as a smooth scale. So when we turn a count into a boundary, we move it by half a person: “more than 105” means 106 or more, so its boundary on the smooth scale is 105.5.

Worked example 3.9

Is the room big enough?

The next event has 120 registrations and the room seats 105. Each registered person attends with probability 0.83, independently of the others.

Calculate the expected attendance and its standard deviation, then estimate the probability that more than 105 people attend. Decide whether we should move to a larger room.

Check the conditions: There are 120 fixed registrations with two outcomes each, the same probability from the records, and we assume independence. \(n p = 99.6\) and \(n (1 - p) = 20.4\), both at least 10, so the normal model applies.

Mean and standard deviation:

\[\mu = 120 \times 0.83 = 99.6\] \[\sigma = \sqrt{120 \times 0.83 \times 0.17} = \sqrt{16.932} = 4.115\]

More than 105: The count “more than 105” begins at 106, so the boundary is 105.5.

\[z = \frac{105.5 - 99.6}{4.115} = \frac{5.9}{4.115} = 1.43\]

The standard normal table gives an area above 1.43 of 0.0764. The spreadsheet’s exact figure, =1-BINOM.DIST(105, 120, 0.83, TRUE), is 0.0710.

Decision: About 7 events in 100 with this registration pattern would have more people than seats. We need to decide whether a 1 in 14 probability of turning people away is acceptable. If a larger room costs little, we should take it. If it is expensive, a waiting list and a reminder to confirm attendance a week ahead would manage the risk at lower cost.

Section summary

A random variable is a number whose value is decided by chance, and its probability distribution lists every value with its probability. The expected value counts each value in proportion to its probability, and it gives the average payoff over many repeats of the same decision. A risk review sets the probability of a loss, the worst outcome and the standard deviation beside the expected value. A decision tree draws decisions as squares, chance events as circles and payoffs as triangles, and rolling it back from right to left identifies the option with the highest expected value. In the vendor scenario file, the international vendor has the higher expected value in all 50 scenarios and the larger loss in 49, so our choice depends on the loss we can absorb. The binomial model counts successes in a fixed number of independent trials, with mean \(n p\) and standard deviation \(\sqrt{n p (1 - p)}\).
